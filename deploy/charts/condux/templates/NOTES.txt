Before it works:
  1. Data stores are BYO — point the chart at your managed Postgres, ClickHouse, Kafka/Redpanda and
     Valkey/Redis via .Values.externalStores.* and provide credentials via the Secret
     (.Values.secret.* inline, or .Values.secret.existingSecret in production).
  2. Migrations run automatically as a pre-install/pre-upgrade hook Job from the `migrations` image
     (build it from deploy/migrations.Dockerfile). It needs native-protocol (9000) access to ClickHouse.
     Set .Values.migrations.enabled=false to apply them yourself.
{{- if .Values.github.enabled }}
  3. The GitHub App (the Conductor) is enabled — ensure the App is installed on your repos and the
     control-plane's public URL is set as the App's setup/webhook URL.
{{- end }}

Two things worth knowing now rather than later:

  Topology: the relay takes ingest, the control-plane serves the API and dashboard, and two workers
  (consumer, conductor) run behind them. Postgres, ClickHouse, Kafka/Redpanda and Valkey are external
  and yours to run; this chart does not bring them.

  Backups: Postgres is the store that cannot be rebuilt. ClickHouse events are large and refill from
  new traffic, so back up Postgres on a schedule and treat ClickHouse as optional.
